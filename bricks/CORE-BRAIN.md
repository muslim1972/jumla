# العقل المعماري والشبكة العصبية لنظام "جملتي" (`CORE-BRAIN.md`)

نظام جملتي مبني على معمارية معزولة طابوقياً (Brick Architecture) تفصل بين المكونات وتمنع تداخل المسؤوليات.

---

## 1. الهيكل والطبقات (Layers)

1. **طبقة التطبيق والمسارات (`src/app/`):**
   - مجموعات مسارات معزولة:
     - `(app)`: الواجهة العامة، السلة، المتجر العام، المحفظة، المكافآت، الإدارة.
     - `(auth)`: بوابات الدخول والتسجيل وانتظار الموافقة.
     - `(merchant)`: لوحة تحكم التاجر، المستودعات، الأرشيف، الفواتير، الديون.
     - `(materials)`: إدارة المواد والتصنيفات والمخزون الأولي.

2. **طبقة الميزات المستقلة (`src/features/`):**
   - كل ميزة (`feature`) معزولة بذاتها وتحتوي على:
     - `actions/` أو `actions.ts`: استدعاءات الخادم (Server Actions) مع تدقيق الصلاحيات.
     - `components/`: مكونات الواجهة الخاصة بالميزة فقط.
     - `hooks/`: خطافات الحالة والاشتراكات اللحظية (Realtime).
     - `lib/`: خوارزميات الحساب والتحويل المحددة للميزة.

3. **طبقة الخدمات المشتركة (`src/components/global/`, `src/lib/`, `src/utils/`):**
   - دوال مساعدة عامة غير مرتبطة بنطاق تجاري واحد (مثل دوال Supabase Client/Server، وتنسيق الأرقام والتواريخ).

4. **طبقة قاعدة البيانات (Supabase DB):**
   - جداول محمية بسياسات RLS مشددة.
   - دوال تنفيذ ذرية (Atomic RPCs) للعمليات المالية والحركات المحاسبية لمنع Race Conditions.

## 2. خريطة الطابوقات (Brick Catalog)

| الرمز | اسم الطابوقة | النطاق | المسؤولية |
|---|---|---|---|
| **FE-CORE-01** | Core Shell & Global UI | واجهة عامة | الغلاف العام، القوائم العائمة، الثيم، الإشعارات العامة |
| **FE-AUTH-01** | Authentication & RBAC | دخول وصلاحيات | تسجيل الدخول، إنشاء الحساب، انتظار الموافقة، التحقق من الدور |
| **FE-PROD-01** | Product Catalog & Search | متجر وتصنيفات | عرض المنتجات، البحث المتقدم، بطاقات المواد، التصنيفات |
| **FE-CART-01** | Shopping Cart | سلة الشراء | إدارة عناصر السلة، حساب الإجمالي والخصم |
| **FE-ORD-01** | Orders & Checkout | طلبات وفواتير | إتمام الشراء، تتبع الطلبات، توليد الفواتير، التقييمات |
| **FE-MERCH-01**| Merchant Dashboard | لوحة التاجر | إدارة منتجات التاجر، المستودعات، الفواتير، الإعدادات |
| **FE-DEBT-01** | Credit & Debts | ذمم وديون | إدارة الديون، المشترين الموثوقين، تسديد المستحقات |
| **FE-WAL-01**  | Wallet & Rewards | محفظة ومكافآت | رصيد المحفظة، عمليات الشحن، نقاط الولاء والمكافآت |
| **FE-DELIV-01**| Delivery Management | إدارة التوصيل | تعيين السائقين، تتبع التوصيل، إدارة المناديب |
| **FE-MAT-01**  | Materials & Barcode | مستودع المواد | إدارة المواد الخام والباركود، الوحدات القياسية |
| **FE-ADMIN-01**| Platform Admin | لوحة الإدارة العليا | إدارة الحسابات، سجل الرقابة (Audit Log)، الإعدادات العامة |
| **BE-DB-01**   | Supabase Core Data | قاعدة البيانات | جداول المستخدمين، المنتجات، الطلبات، المحافظ، ودوال RPC الذرية |

## 3. سجل القرارات المعمارية

### [2026-10-14] DEC-04: استيراد مرشحين من كتالوجات مفتوحة إلى Pool
- البحث الخارجي محصور بمصادر Open Facts المحددة (غذاء، تجميل، طعام حيوانات، منتجات عامة تجريبية) وعبارات بحث يطلقها المدير يدوياً؛ ليس زاحفاً عاماً للإنترنت ولا عاملاً دائماً.
- النتائج تحفظ في `catalog_import_candidates` كمرشحين ولا تدخل `master_products` إلا بعد مراجعة ADMIN.
- المطابقة بالاسم الموحّد أولاً ثم الوصف؛ الباركود معلومة اختيارية ولا يمثل مفتاح هوية أو قيداً فريداً، ومسار الإضافة إلى المخزن يطابق بالاسم والوصف.
- ترحيل `scripts/catalog/09-external-catalog-import.sql` يضيف سجل المراجعة، حدود البحث، بيانات المصدر والترخيص، وفهرس الاسم والوصف، ويزيل فهرس الباركود الفريد. يجب التحقق من التكرارات الموجودة وتطبيق الترحيل يدوياً قبل نشر الواجهة؛ لا يُنفذ تلقائياً على Supabase.
- اعتماد المرشح وإنشاء مادة Pool يجريان ذرياً عبر RPC يقفل صف المرشح، مع حد 10 عمليات بحث لكل مدير في الدقيقة وإقرار صريح بشروط ODbL وCC BY-SA.
- صور Open Facts الخارجية تُقيد بمضيفات معروفة، ويُحفظ رابط المصدر والترخيص ويُعرض الإسناد في واجهة الكتالوج والمتجر.
