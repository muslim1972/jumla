# ذاكرة معمارية جملتي (Jumla Architecture Skill)

> **تحذير لكل وكيل:** هذا الملف هو الذاكرة المستمرة للمشروع عبر الجلسات. اقرأه كاملاً قبل البدء بأي عمل.
> كل إنجاز أو قرار يوثق هنا **بالإلحاق** (append-only) ولا يُمسح القديم إطلاقاً.

---

## 1. هوية النظام والمواصفات التقنية
- **المنصة:** نظام تجارة الجملة المتكامل (العراق).
- **البيئة التقنية:** Next.js 16.2.6 (App Router + Turbopack) + React 19.2.4 + Tailwind CSS v4.
- **قاعدة البيانات:** Supabase Cloud (باقة مجانية بدون نسخ احتياطي — كل تغيير SQL يجب أن يكون مدروساً وموثقاً).
- **الاستضافة والنشر:** Vercel متصل بـ GitHub Repo (`https://github.com/muslim1972/jumla.git`) — النشر أوتوماتيكي عبر `main`.

---

## 2. الدرع الواقي وحارس الطابوق
- **دستور المشروع:** `AGENTS.md` في جذر `D:\jumla\`.
- **أمر فحص الحارس:**
  ```powershell
  node scripts/verify-bricks.mjs
  ```
- **فحص الأنواع قبل الاعتماد:**
  ```powershell
  npx tsc --noEmit
  ```
- **بناء الإنتاج قبل الدفع:**
  ```powershell
  npm run build
  ```

### [2026-10-11] DEC-01: تأسيس الدرع المعماري وجدار الطابوق
- **الدافع:** تكرار الأخطاء والتراجعات العشوائية وتراكم سكربتات الترقيع في الجذر.
- **القرار:**
  1. أرشفة كافة السكربتات المؤقتة في `_archive/`.
  2. صياغة دستور صارم `AGENTS.md` يمنع المجاملة والتخمين و `setTimeout` ويفرض التحقق قبل النشر.
  3. بناء جدار الطابوق (`bricks/registry.json`) لتغطية 100% من ملفات `src/` بدون أي ملف يتيم أو متداخل.
  4. إنشاء سكربت حارس الطابوق `scripts/verify-bricks.mjs` مع تتبع بصمات الملفات (`fingerprints.json`).
  5. ربط قاعدة البيانات وفهرسة جداولها ودوالها في الطابوقات المعنية.

### [2026-10-12] DEC-02: تصميم نظام الطرح المخزني المشروط بالرقابة الثنائية (Dual-Approval Deduction)
- **الدافع:** طلب ميزة شطب/طرح مواد للموظفين (إتلاف/بيع خارجي) وحماية رصيد المخزن من العجز أو التلاعب بالاتفاق الثنائي.
- **القرار والتنفيذ:**
  1. إنشاء جدول `warehouse_deduction_requests` مع فهارس وسياسات RLS، ودالة RPC ذرية `warehouse_process_deduction_decision`.
  2. إضافة تبويبة "طرح من المخزن" في نافذة الصنف (`WarehouseItemDialog`) بموقع المستطيل الأحمر، وإلزام اختيار الموظف الشاهد إن وجد أو توجيه الطلب للتاجر إن كان موظفاً وحيداً.
  3. حماية تبويبة "حركة مخزنية" ومنع الإخراج المباشر أو تسوية الجرد للموظفين لإلزامهم بمسار طلب الطرح المعتمد.
  4. بناء تبويبة "طلبات الطرح" في لوحة المخازن (`WarehouseHub`) مع شارات التنبيه وأزرار اتخاذ القرار التفاعلية (تأييد/اعتماد/رفض) وإشعارات لحظية لجميع الأطراف.
  5. اجتياز حارس الطابوق (157/157 ملف بنسبة 100%)، وفحص الأنواع الصارم (0 أخطاء)، وبناء الإنتاج بنجاح تام.

### [2026-10-13] DEC-03: إصلاح استعلام حركات المخزن (PostgREST PGRST201) وتوحيد وحدات العرض
- **الدافع:** اختفاء حركات المخزن المعتمدة من تبويبة "آخر الحركات" للصنف ومن "دفتر الحركات" رغم ثبوتها في قاعدة البيانات.
- **التشخيص والحل:**
  1. كشف خطأ `PGRST201` بسبب وجود مفتاحين أجنبيين بين `warehouse_movements` و `profiles` (`merchant_id` و `performed_by`)، وتم حله بتحديد العلاقة صراحة: `actor:profiles!warehouse_movements_performed_by_fkey(full_name)`.
  2. إضافة فحص وتسجيل أخطاء `movementsRes.error` بدلاً من ابتلاعها بصمت.
  3. مواءمة كميات ورصيد الحركات في نافذة الصنف مع وحدة العرض الحالية المعتمدة (كيس/كارتون) باستخدام `baseToDisplay` لتتطابق أرقام الحركة مع رصيد الترويسة، وتمييز شارة "طرح معتمد" وفك اختصار الملاحظات لقراءتها بالكامل.
